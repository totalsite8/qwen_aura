# Aura Demo

**Aura** — персональный умный помощник по поиску товаров и услуг. Вы пишете одну фразу — Aura уточняет детали,
сравнивает варианты, проверяет надёжность и объясняет, почему выбрала лучшее.

Это **кликабельный демо-прототип** (режим DEMO_MVP): все данные — учебные, вся «работа помощника» — реалистичная
симуляция с задержками и живыми статусами. Настоящих покупок, рассылок и интеграций здесь нет.

---

## Как запустить

Нужен Node.js 18+ и npm.

```bash
npm install     # установка зависимостей
npm run dev     # локальный запуск (адрес покажет терминал)
npm run build   # производственная сборка в папку dist
npm run preview # предпросмотр собранной версии
```

Полезно для быстрой проверки: добавьте `?fast=1` к адресу — все анимации поиска ускорятся до ~1–2 секунд.

## Что проверить в демо (чеклист)

1. **Главный экран** — чистый, по центру плавающая строка ввода с мягким стеклом и тенью, рядом «дышащая» сфера.
2. **Подсказки** — начните вводить: список подсказок с типами (Товар / Подбор / Подарок / Услуга).
   Работают стрелки ↑/↓, Enter — выбор, Esc — закрыть.
3. **Сценарий «Точный товар»** — запрос `Honor Magic 7 Pro`:
   - панель «Что я сейчас делаю» — живой «веб-поиск»: печатаются запросы, сканируются Ozon/WB/Яндекс Маркет/DNS/М.Видео
     со счётчиками предложений, «открываются» страницы обзоров, сравниваются цены магазинов. По завершении панель
     схлопывается в итог, сверху — сводка «Что я сделала» (кнопка «Как я это сделала» разворачивает лог);
   - бенто-выдача: большая плитка «Выбор Aura» (цена как есть + «+баллы, если купите так»), «Честный расчёт»
     (честно: если есть дешевле — так и написано), кольцо «Проверка надёжности»;
   - 4 дополнительных варианта появляются каскадом;
   - аналитика под рукой: индикатор «ниже/выше средней», динамика цены с подсказкой при наведении,
     «Что говорят покупатели», «Почему мы это выбрали», полное сравнение (открывается модалкой).
4. **Сценарий «Категория»** — запрос `Беспроводные наушники до 3 000₽`:
   4 вопроса кликабельными карточками → чипы-сводка → поиск → «Выбор Aura» + 5 вариантов + дашборды.
5. **Сценарий «Подарок»** — запрос `Подарок парню на 23 февраля`:
   4 вопроса → заботливая подборка: главный «Выбор Aura» + 3 направления подарков с альтернативами.
6. **Сценарий «Услуга»** — запрос `Остеклить балкон`:
   4 вопроса → карточка «Поняла задачу» → процесс «Отправила в проверенные компании… Получаю ответы…» →
   4 компании с рейтингами, ценами и отметками (включая «Возможны скрытые доплаты») → «Рекомендация Aura» →
   блок «На что обратить внимание» → «Выбрать» → «Открыть контакт» (демо-модалка, без реальных данных).
7. **Темы** — переключатель «Светлая / Система / Тёмная» справа сверху; выбор сохраняется после перезагрузки.
8. **Баллы Aura** — кошелёк в шапке: баланс, объяснение («баллы бесплатны»), реферальный блок
   «Порекомендуй другу — получи 1000 баллов», кнопка «Поделиться» копирует демо-ссылку.
9. **Сфера и PWA** — клик по сфере: установка приложения, если браузер её поддерживает,
   иначе аккуратная пошаговая подсказка (отдельно для iPhone). Есть manifest и минимальный service worker.
10. **Страница для исполнителя** — адрес `#/smart-link/demo`: «Новый заказ в вашем районе», одно поле «Ваша цена»,
    кнопка «Отправить цену», экран успеха. Без регистрации и кабинета — демонстрация принципа «ноль трения».
11. **Нераспознанный запрос** — например, «абракадабра»: никакого «ошибочного» вида, дружелюбное уточнение
    с примерами-подсказками.
12. **Кнопки «Купить с баллами» / «Купить без баллов»** — аккуратная модалка «Демо-режим», без перехода в магазин.

### Примеры запросов для проверки

## Где что лежит

- `src/data/queries.ts` — 4 списка по 20 запросов и «затравки» для генератора правдоподобных результатов.
- `src/data/products.ts` — полностью проработанные hero-наборы (Honor Magic 7 Pro, наушники, подарки)
  и генераторы товаров/компаний для остальных запросов.
- `src/data/scenarios.ts` — вопросы, шаги процесса «Что я сейчас делаю», hero-данные услуг, сборка сценария.
- `src/lib/classify.ts` — клиентская имитация понимания запроса (списки → эвристики → мягкий fallback).
- `src/components/SearchPage.tsx` — машина состояний поиска: уточнение → работа → результат.
- `src/features/` — тема, кошелёк с баллами, PWA-установка.
- `public/` — manifest, service worker, иконка.

Стек: React + Vite + TypeScript (strict) + Tailwind CSS + Framer Motion + Zustand + React Router + Lucide + sonner.

## Допущения, принятые в демо

1. **Ответы на уточняющие вопросы не меняют сам набор результатов** — они честно показываются в сводке
   («Поняла задачу», чипы), но выдача в демо фиксированная (hero-наборы и генератор). В рабочем продукте
   ответы будут влиять на подбор.
2. **Цены, рейтинги, отзывы, истории цен и названия продавцов/компаний — вымышленные**, подобраны правдоподобно.
3. **Баллы НЕ вычитаются из цены** (решение основателя): цена показывается как есть; отдельно указывается
   «+N баллов Aura, если купите так» и что магазин надёжнее. Если у других вариантов цена ниже — честно пишем об этом
   в плитке «Честный расчёт».
4. **Баллы начисляются демонстрационно**: при «покупке с баллами» бонус появляется в кошельке с пометкой «демо», цена не меняется.
5. **Процесс подбора — симуляция «настоящего веб-поиска»**: запросы печатаются, магазины (Ozon, Wildberries,
   Яндекс Маркет, DNS, М.Видео и др.) «сканируются» со счётчиками, страницы «открываются», цены сравниваются.
   Все цифры в ленте согласованы с итоговой выдачей. По завершении процесс схлопывается в итог
   («N предложений · M магазинов · ~9 с») + сводка «Что я сделала».
6. **Выдача — высокотехнологичное бенто**: главный выбор, честный расчёт, кольцо надёжности, динамика цены
   с подсказкой при наведении, индикатор «дешевле/дороже средней», отзывы, полное сравнение (модалка) — всё под рукой,
   плюс липкая навигация по секциям (Итог / Выбор Aura / Варианты / Аналитика).
5. **Город в сводке услуги** показан как «Ваш город» — без геолокации.
6. **Service worker регистрируется только в собранной версии**, чтобы не мешать разработке.
7. **Иконка PWA — векторная (SVG)**; на очень старых системах установка может быть недоступна, тогда показывается
   пошаговая подсказка — это задуманное поведение, а не ошибка.

## Чего в демо нет (и не должно быть)

- настоящей оплаты и списания денег;
- реальных переходов в магазины;
- реальных отправок задач компаниям, звонков и рассылок;
- реального сбора и хранения персональных данных (форма контакта никуда не отправляет);
- реального поиска по сайтам — всё имитируется локально.

2. Сделать ответы на вопросы реально влияющими на выдачу (фильтры и ранжирование).
3. Реальный поток заявки на услугу: подтверждение → контакт → статусы.
4. Настоящая выдача и списание баллов по правилам программы.
5. Полноценная PWA-установка с PNG-иконками под все платформы и офлайн-режимом.
6. Аналитика поведения в демо (где люди «отваливаются») перед запуском.
